# 보안 리포트 — 점수·완독 기록 위조 가능성 + SSO 연동 잠금 계획

*작성: 2026-07-10 / 실측: Supabase ref gkujptyfrzqrjrvovbnc / 대상: klever_demo app.html*

## 한 줄 요약
현재 학생 데이터는 **인증이 없고**(브라우저 이름표 하나로 신분 결정), 모든 테이블이 **anon 무제한 읽기·쓰기·삭제** 상태다.
점수·완독율도 브라우저가 계산해 서버가 그대로 믿는다. **지금은 실학생 0이라 위험 0. 8월 학생 유입 전에 SSO와 함께 잠근다.**

## 왜 지금 못 잠그나 (중요)
완전 차단하려면 서버가 "이 요청자가 진짜 그 학생인지" 검증할 수 있어야 하는데, 그건 **진짜 로그인(SSO)이 있어야** 가능하다.
지금은 anon 키 하나로만 접근하므로, RLS를 조이면 데모 자체가 멈춘다. → **SSO 도착 = 잠금 실행 시점.**

## 실측 결과 (2026-07-10)

### 1) RLS 정책: 전 테이블 무방비
bookstar_* 16개 테이블 전부 RLS는 켜져 있으나 정책이 `cmd=ALL, qual=true, with_check=true`, roles=`{anon}`/`{public}`.
→ **누구나 어떤 행이든 SELECT/INSERT/UPDATE/DELETE 가능.** (점수 조작뿐 아니라 남의 기록 삭제·덮어쓰기까지)

주요 대상: bookstar_challenge_results(점수·완독), bookstar_reader_stats(독서시간), bookstar_students,
bookstar_student_totals(별), bookstar_writings, bookstar_likes, bookstar_follows 등.

### 2) 인증 부재
- 신분 = `localStorage['bookstar-current-student']` 값 하나. 비밀번호·토큰·서버 세션 없음. (app.html bxStudent)
- 임의 student_id 사칭 가능: 콘솔에서 `localStorage.setItem('bookstar-current-student', JSON.stringify({id:'남의학번'}))` 한 줄.
- 모든 서버 쓰기가 body의 `student_id`를 이 값에서 가져옴 → 타인 명의 조작 가능.

### 3) 점수·완독율 클라이언트 계산 → 서버 무검증 저장
- 점수: `score = ok*10 + (submitted?50:0)` 를 브라우저가 계산해 bookstar_challenge_results에 upsert. 정답 여부(ans.ok)도 로컬값.
- 완독율: read_pct/read_sec 를 브라우저가 계산해 그대로 전송(v4 로직도 클라측).
- anon 키가 HTML에 하드코딩(COVER_ANON) → 앱 UI 없이 curl로도 직접 호출 가능.

### 4) 서버 로직 여지
`award_activity` 등 RPC는 서버 함수 내부에 검증이 있을 수 있음(별도 감사 필요). 순수 REST upsert(점수·완독)는 서버 검증 전혀 없음.

## SSO 도착 시 잠금 계획 (초안 — 인증 방식 확정 후 확정)

> 전제: SSO가 Supabase Auth(또는 학번을 담은 검증된 JWT)를 발급해, 서버가 요청자의 학번을 신뢰할 수 있게 된다고 가정.
> JWT에 학번 클레임(예: `student_id` 또는 `sub`)이 들어온다는 전제. 실제 클레임 경로는 SSO 규격 확정 후 확정.

### 원칙
1. **본인 행만 쓰기**: RLS with_check 를 "요청자 학번 == 행의 student_id"로.
2. **점수는 서버가 재계산**: 클라가 보낸 score를 믿지 않음. 정답키는 서버(RPC, SECURITY DEFINER)만 보유하고, 제출 답안으로 서버가 채점·저장.
3. **읽기는 필요 범위만**: 리더보드·대시보드용 집계는 공개 뷰/RPC로 제공(개별 원본 테이블 전체 SELECT는 축소).
4. **anon 쓰기 제거**: authenticated 롤만 쓰기 허용.

### 잠금 SQL 초안 (예시 — bookstar_challenge_results)
```sql
-- 1) 무제한 정책 제거
DROP POLICY IF EXISTS anon_all_results ON bookstar_challenge_results;

-- 2) 읽기: 로그인 사용자에게 허용(리더보드/대시보드용). 필요시 집계 뷰로 더 좁힘
CREATE POLICY results_read ON bookstar_challenge_results
  FOR SELECT TO authenticated USING (true);

-- 3) 본인 행만 삽입/수정 (JWT 학번 클레임 == student_id)
CREATE POLICY results_write_own ON bookstar_challenge_results
  FOR INSERT TO authenticated
  WITH CHECK (student_id = (auth.jwt() ->> 'student_id'));
CREATE POLICY results_update_own ON bookstar_challenge_results
  FOR UPDATE TO authenticated
  USING (student_id = (auth.jwt() ->> 'student_id'))
  WITH CHECK (student_id = (auth.jwt() ->> 'student_id'));
-- DELETE 정책은 만들지 않음 → 삭제 차단
```

### 점수 서버 재계산 (RPC 초안)
```sql
-- 정답키(quiz_items.correct)는 서버만 접근. 클라는 답안만 제출, 서버가 채점·score 저장.
CREATE OR REPLACE FUNCTION submit_quiz(p_book_id text, p_answers jsonb)
RETURNS integer
LANGUAGE plpgsql SECURITY DEFINER AS $$
DECLARE v_sid text; v_ok int; v_total int; v_score int;
BEGIN
  v_sid := auth.jwt() ->> 'student_id';
  IF v_sid IS NULL THEN RAISE EXCEPTION 'unauthenticated'; END IF;
  -- p_answers({scene_no:선택지}) 를 quiz_items.correct 와 대조해 v_ok/v_total 산출 (서버 내부)
  -- v_score := v_ok*10 + (완주여부?50:0);
  -- bookstar_challenge_results 에 서버가 upsert (student_id=v_sid 강제)
  RETURN v_score;
END $$;
```
→ 클라의 bxUpsertResult(점수 직접 전송)를 이 RPC 호출로 교체. read_pct/read_sec도 서버 상한 검증(예: read_sec ≤ 전체글자×0.08 등) 후 저장.
