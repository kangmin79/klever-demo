## ⏳ 미해결(별도 작업): 큰 책 파일 3배 부풀림
- **문제**: 큰 책 bodies가 8~10MB(gzip 3~4MB). BODIES_SENT(문장정렬 [원문,번역]쌍) + BODIES_ORIG(원문 전체) + BODIES_TRANS(번역 전체)를 **중복 저장**. SENT가 이미 원문·번역을 담으므로 ORIG/TRANS는 사실상 중복.
- **앱은 이미 SENT 우선 렌더**(app.html ~6868: BODIES_SENT[id] 있으면 그걸로). ORIG/TRANS는 폴백(6875~6878).
- **개선안**: bodies 빌더(_drive.py, Desktop/클레버, git 아님)가 ORIG/TRANS를 빼고 SENT만 출력 → 파일 ~1/3. 큰 책 10MB→3~4MB(gzip 1~1.5MB).
- **위험/선결**:
  1. "원문만 보기" 문단 구조 검증 — ORIG는 원 문단(\n\n) 보존, SENT는 문장 단위라 문단 경계가 다를 수 있음. SENT에서 원문 재구성 시 문단 렌더가 깨지지 않는지 확인 필수.
  2. 앱 렌더 경로에서 ORIG/TRANS 폴백 쓰는 책(legacy, SENT 없는 책) 영향 확인.
  3. 빌더 변경 + 143권 재빌드 + 재배포(대용량 커밋).
- **판단**: 임팩트 크나(큰 책 열기 체감 개선) 위험도 큼 → 전용 세션에서 1권 먼저 검증 후 전체.
