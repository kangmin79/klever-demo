# 도서 데이터 도착 체크리스트 (세명대 종이책·전자책)

*작성: 2026-07-10 / 대상 테이블: public.semyung_new (ref gkujptyfrzqrjrvovbnc)*

## 결론 먼저
**적재 파이프라인은 이미 완성돼 돌아가고 있다.** 새로 만들 것 없음.
현재 semyung_new에 종이책 206 + 전자책 116 = 322건 적재됨. 세명대에서 데이터가 오면 아래 절차로 기존 파이프라인에 흘려보내면 된다.

## 대상 테이블 스키마 (semyung_new)
`brcd`(PK), `title`, `author`, `publisher`, `pub_year`, `pub_date`, `isbn13`, `cover`(URL), `store`, `detail`(도서관 상세 URL), `summary`, `kind`("종이책"|"전자책"), harvested_at, updated_at
- **키**: `brcd` — 종이책 = `CATTOT`+reckey, 전자책 = 숫자 컨텐츠코드
- **upsert**: `POST /rest/v1/semyung_new?on_conflict=brcd` + `Prefer: resolution=merge-duplicates` (멱등)

## 기존 파이프라인 (klever_demo/)
- 실행 진입점: `_semyung_sync.bat` (로컬 전용 — 세명대가 미국 IP 차단해 GitHub Actions 불가)
- 종이책 신착: `scripts/build_semyung_new_paper.py`
- 전자책 신착: `scripts/build_semyung_new.py`
- 대출랭킹: `scripts/build_semyung_loan_rank.py` → semyung_loan_rank
- 줄거리 보강: `scripts/desc_semyung_new_paper.mjs`, `desc_loan_rank.mjs`
- 표지/메타 보강: `scripts/enrich_semyung.mjs`, `enrich_semyung_holdings.mjs` → `books/semyung_enrich.json`
- 실행 환경: Python 3.10, Node.js (경로는 _semyung_sync.bat 참조), service_role 키는 스크립트 내

## 데이터가 도착하면 (형식별 분기)

### 경우 1: 세명대가 "우리 시스템(OPAC/전자도서관)에서 계속 긁어라"
→ **할 일 거의 없음.** 기존 build 스크립트가 이미 그 소스를 긁는다. `_semyung_sync.bat`를 작업 스케줄러에 매일 1회 등록만 확인.
- [ ] 작업 스케줄러 등록 상태 확인 (한글 경로 침묵실패 주의 — %~dp0 사용)
- [ ] logs/semyung_sync.log 에 최근 성공 기록 확인

### 경우 2: 세명대가 "파일(엑셀/CSV/API)로 장서 목록을 준다"
→ 그 파일을 semyung_new 스키마로 매핑하는 어댑터 스크립트 1개만 신규 작성.
- [ ] 받은 파일 컬럼 → semyung_new 필드 매핑표 작성 (title/author/publisher/isbn13/kind 필수)
- [ ] brcd 생성 규칙 확정 (종이책 CATTOT+reckey / 전자책 컨텐츠코드 / 없으면 isbn13 기반 대체키)
- [ ] 어댑터 스크립트: 파일 읽기 → 필드 매핑 → `on_conflict=brcd` upsert (build_semyung_new.py의 upsert 부분 복사)
- [ ] 표지·줄거리 없으면 enrich_semyung.mjs 로 보강 (종이책=알라딘 ISBN 조회)
- [ ] 소량(10건) 시험 upsert → app.html '우리 도서관'에서 노출 확인 → 전량
