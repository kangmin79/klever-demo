# 세명대 장서 정식 설계 v1 (MVP → 정식)

*작성: 2026-07-10 / 상태: 설계 확정 대기(퓨처누리 데이터 형식 미정) / 종이책=퓨처누리, 전자책=교보(별도 소스)*

## 목표
데모용 semyung_new(급조된 신착 표시용)를 버리고, **도서관 장서를 제대로 관리할 정식 구조**로 재설계.
퓨처누리(종이책)·교보(전자책)에서 오는 실데이터를 하나의 깔끔한 구조로 통합 관리.

## 지금 구조(semyung_new)의 한계
- 필드가 "신착 몇 개 보여주기"용 — 장서 관리에 필요한 **등록번호·청구기호·소장위치·자료유형·주제분류(KDC)** 없음
- 종이책/전자책을 `kind` 문자열로만 구분, 소스 추적(어디서 왔나) 약함
- 하드 삭제 구조 — 실수로 날리면 복구 불가
- 현재 데이터=데모 322건(종이206+전자116). 실장서 아님.

## 정식 스키마 (제안) — 단일 통합 테이블 `library_catalog`

종이책·전자책을 **한 테이블 + material_type 구분**으로 통합. 검색·표시 로직이 하나로 일관됨.

| 필드 | 설명 | 종이 | 전자 | 비고 |
|---|---|:-:|:-:|---|
| id | PK (uuid) | ✓ | ✓ | 내부 고유키 |
| material_type | 'paper' \| 'ebook' | ✓ | ✓ | 자료유형 |
| source | 'futurenuri' \| 'kyobo' | ✓ | ✓ | 데이터 출처(재동기화·중복제거 축) |
| source_id | 원본 시스템 식별자 | ✓ | ✓ | 퓨처누리 등록번호 / 교보 컨텐츠코드. (source, source_id) 유니크 |
| isbn13 | ISBN | ✓ | ✓ | 종이↔전자 같은 책 연결·중복판별 축 |
| title | 서명 | ✓ | ✓ | |
| author | 저자 | ✓ | ✓ | |
| publisher | 출판사 | ✓ | ✓ | |

| kdc | 한국십진분류(주제) | ✓ | △ | 주제별 브라우징용 |

**실시간 대출 가능 여부**는 이 테이블에 저장하지 않음 — 세명대 OPAC이 진짜 소스라, 기존 Edge Function(semyung-holding)으로 상세 화면에서 실시간 조회.

## 설계 원칙 (제대로의 핵심)
1. **통합**: 종이+전자 한 구조 → 검색·카드 표시 로직 1벌.
2. **소스 추적**: (source, source_id) 유니크 → 매일 재동기화 시 멱등 upsert, 중복 없음.
3. **soft delete**: active 플래그 → "기존 데이터 전부 삭제"도 active=false로 안전하게(진짜 삭제 아님). 실수 복구 가능.
4. **ISBN 축**: 같은 책의 종이·전자를 isbn13으로 묶어 "이 책, 전자책도 있음" 표시 가능.

## 마이그레이션 계획 (데이터 도착 시 실행)
1. `library_catalog` 테이블 신규 생성(병행 운영, 기존 semyung_new 안 건드림)
2. 퓨처누리 종이책 → 필드 매핑 → 적재(소량 시험 → 전량)
3. 교보 전자책 → 필드 매핑 → 적재
4. 앱 코드를 semyung_new → library_catalog로 전환(아래 연동 지점)
5. 검증(건수·빈필드·앱 표시) 통과 후 semyung_new 폐기(즉시 DROP 대신 아카이브 후 정리)

**"기존 데모 데이터 전부 삭제" 방식**: 새 테이블로 병행 구축 → 검증 → 스위치. semyung_new는 마지막에 비움. (한 번에 삭제+삽입보다 안전 — 중간에 앱이 빈 화면 되는 것 방지)

## 지금 안 하는 이유
데이터 형식이 미정이라 컬럼을 지금 확정하면 재작업 위험. **구조·원칙은 이 문서로 확정**, 실제 테이블 생성·적재·앱 전환은 데이터 도착 후 한 번에.
